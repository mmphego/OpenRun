## Delivered

`OpenRun-1.4.4-device-QA-kit.zip` includes the unchanged APK, existing isolated-preference instrumentation APK and S23 acceptance checklist, plus:

- `mac-qa.sh`: Mac entry point for emulator download/boot/UI checks, S23 install, locked-walk start/end evidence and release gate. No Samsung account needed.
- `emulator_runner.py` / `ui_smoke.py`: AOSP Android 16 boot and UI-tree-driven plan, race, auto-advance, large-font and indoor-entry checks. Model weights, live Garmin and race-feed services are outside this suite.
- `s23_locked_walk.py`: exact-installed-APK verification; start/end recording UI values; 31-minute screen-off service/power sampling. It never starts, pauses, saves or discards an app recording. `s23-finish` captures end values after manual unlock; it does not finish the app session.
- `physical-review.json`: pending review template for independent 200-step accuracy, calibrated machine-distance error, same-session continuity, notification Finish, pause/resume, single save/totals and interrupted recovery.
- `release_gate.py`: refuses missing, pending, failed or different-APK evidence. Initial acceptance targets: ≤10% error over 200 independently observed steps, ≤15% distance error after personal calibration at the tested speed, 30+ sampled screen-off minutes, timer drift ≤30 seconds, no paused/partial endpoints or absent-service samples. These are initial product targets, not universal hardware guarantees or medical accuracy claims.
- `package_candidate.py`: creates a recording-QA-cleared candidate archive only after the gate passes. It never overwrites an existing archive. Debug builds remain available to test fixes.
- Synthetic QA-tool tests, README and actual blocked-host evidence.

`OpenRun-1.4.4-QA-source.zip` retains the original source and adds this testing workflow and evidence report. It does not include the emulator SDK/image binaries; the Mac runner downloads the correct architecture from the local SDK manager.

## Next execution on your Mac

Install Android Studio's SDK Command-line Tools and Python 3.10+, extract the kit, open Terminal in that folder:

```bash
bash mac-qa.sh emulator
```

Then save active OpenRun sessions, connect/authorize the S23 over USB and follow README.md for `s23-install`, `s23-walk`, `s23-finish` and `gate`. Keep the Mac awake. Use the walking pad with the phone in your pocket. The script leaves the app recording after collection; finish and save deliberately from the app/notification.

The locked test requires start/end values from the same uninterrupted walk. It checks endpoint progress and sampled service/screen state; it does not observe each physical step while asleep. Review that continuity manually. USB charging/adb activity changes power behaviour; repeat an unplugged locked walk before launch. Complete the wider existing checklist for battery, reminders, outdoor GPS, permissions, Health Connect and accessibility. Review screenshots/logs for personal information before sharing them.

No publishing pipeline is configured here. The new local packaging command enforces the recording gate for packages it creates; the eventual CI/store publishing workflow must invoke the same gate. Production signing, Play/Health Connect declarations, qualified coaching review, Garmin partner access, live SA race feeds and physical Gemma performance remain separate launch requirements.
