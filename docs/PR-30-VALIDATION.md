# PR #30 stabilisation and acceptance

Audit date: 2 November 2026. Scope: existing `feat/ai-connections-settings` branch,
[PR #30](https://github.com/mmphego/OpenRun/pull/30). No new PR or merge is authorised.

## Corrections

- Retained the API 26 stream-collection fix. No minimum-SDK changes, lint baselines,
  disabled tests or relaxed release checks were introduced.
- Freeze each preview together with its original plan/history fingerprint. Rendering
  cannot make an old AI proposal appear fresh. New history, a hold, a changed plan or
  revoked/rotated settings prevent acceptance. Returning to edit regenerates the baseline.
- Preserve validated AI output across activity recreation. Do not put API keys in saved
  instance state. A cancelled/obsolete generation cannot replace a newer preview.
- Offer complete schedule/instruction review before committing. Save the accepted
  schedule and creation explanation/provider/evidence atomically; plan replacement
  keeps activities, matches and recovery holds. Creation is recorded but cannot undo
  into an old plan identity.
- Include goal pace, recent timed pace, long-run day and hold context in full-plan
  evidence. Exclude stale/future runs and keep unreported imported feedback unknown.
  Full-plan responses cannot inject the executable Coach pace marker to bypass the
  separate post-run pace validator. Quality and run/walk prescriptions stay deterministic. Full-plan volume remains
  inside the deterministic safety envelope; this is bounded personalisation.
- Normalise full-plan distances to the existing 0.1 km precision before preview.
  New post-run AI overrides retain their precise accepted values; old overrides retain
  legacy rounding. The optional `precise` override field is additive and validated;
  existing schedules remain readable without a destructive migration.
- Apply keep/retry/pause policies consistently. Retry transient network, HTTP 429 and
  server failures only when selected; reject invalid/incomplete outputs without retries.
  Failures from an old credential revision cannot pause or overwrite new settings.
- Count explicit imported matches once, exclude them from next-run suggestions, keep
  skipped due workouts in the planned denominator, and inspect pain across all runs.
  Keep long change histories out of the compact progress summary; link to full history.
- Give provider/failure-policy selectors accessible labels. Use relative dates in race
  UI fixtures; changing a label to another fixed future event merely postpones failure.

## CI root causes

[Run 41432611862](https://github.com/mmphego/OpenRun/actions/runs/41432611862)
failed Android lint because `Stream.toList()` requires API 34 while the minimum is 26.
Commit `314e8714cd075445dd8e8ac7ad86dfd7d8439295` changed it to
`collect(Collectors.toList())`; [run 41434061423](https://github.com/mmphego/OpenRun/actions/runs/41434061423)
passed. The earlier UI fixture changes used absolute 2026 event dates; this audit
replaces those date-dependent expectations with execution-relative event dates.

The first local stabilisation run found three failures in the new onboarding tests:
assertions ran before AlertDialog's posted click listeners. Explicitly draining the
main looper after those clicks fixes the tests without changing application behaviour.

## External acceptance still required

- No real OpenAI/Gemini keys are available. Live generation, key revocation, billing,
  quotas and account-specific model access are unverified. No credentials were requested
  for inclusion in repository fixtures.
- `adb devices` reports no attached device. Physical Samsung acceptance, encrypted-key
  retention through an in-place upgrade, actual notification permissions/delivery,
  JobScheduler timing, OEM interruption and TalkBack remain unverified. Robolectric
  screenshots are host renders, not device screenshots.
- No production signing credentials were used. Debug APK verification does not establish
  an in-place upgrade from the user's installed signed app. No tag, release or deployment
  is performed by this task.
- Training rules and generated prose have not been validated by a qualified running
  coach. Validation constrains executable schedules; it cannot prove free-form advice safe.

Per [AI Coach release gates](AI-COACH.md#release-gates-required-before-marking-pr-ready),
the PR remains draft until live-provider, physical-device and signed-upgrade acceptance
have evidence. Automated success is not a claim that these external gates passed.
